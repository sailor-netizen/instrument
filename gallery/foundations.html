Foundations

The primitives every component is built from: three token layers, a set of colour roles, two type voices, one spacing ramp, three border weights, one radius axis and a four-step motion budget. Everything on this page is drawn from the live cascade, so switching theme in the bar re-reads the whole page — the swatches, the ramps and the resolved pixel sizes are the running system's values, not a screenshot of them.

The three layers

A theme in this system is not a palette. That is the mistake worth naming first: five colour swaps over one skeleton produce five versions of the same product, and the skeleton is usually what someone means when they say they don't like how it looks. So a theme owns three layers, and a theme file may override all three.

L0 · palette --_paper  --_amber-dk Private literals, --_ prefixed, never consumed by a component. This is the only place a hex or an alpha colour is legal outside a theme file, which makes the lint rule one sentence — a hex outside a theme file or the L0 block is a violation — and makes a re-skin a ten-line edit instead of an audit. npm run check enforces it, on this page too.
L1 · roles --i-signal  --i-line Semantic tokens. What components actually consume, and the only colour vocabulary they have. A component that needs a new literal is telling you the system is missing a role — the fix is a new role here, not a one-off in the component.
L2 · structure --x-radius  data-surface How components draw and where the shell puts things. Scalars are --x- custom properties; modes are rules keyed on data-* attributes. This is the layer a palette-only system doesn't have, and it is why Terminal can delete every box in the product without a screen knowing.

Why the split

Each layer is enforced by different machinery, which is the real reason they are separate rather than one flat list. L0 is containment — literals in one block are greppable. L1 is the cascade — a role resolves through light-dark() driven by exactly one color-scheme declaration, so a theme can never half-switch. L2 splits again by the same logic: scalars live in CSS because the cascade is the right enforcement for a size, while modes live in the registry because applyTheme() writes them all as attributes in one pass — which is what makes a half-applied theme impossible.

Everything hangs off one attribute, data-theme. There is no second switch to forget, so the palette can never change while the layout doesn't.

The current theme's L2, live

Scalars below are read out of the running cascade with getComputedStyle; modes are read from the registry object applyTheme() returned. That is the split, visible: one half is CSS, the other half is JavaScript, and neither can be set without the other landing too. Some scalars print as the calc() they actually are.

Colour roles

Roles, not colours. A theme picks the hue; it never repurposes the role — --i-crit is "this failed" in every theme, forever. That single rule is why nine screens stay correct across six themes without a component ever asking which one is running. Adding a role means stating a need as a sentence about meaning ("a run the verifier could not judge"), not about appearance ("a yellowish tag"); if the sentence is about appearance, an existing role already covers it.

Surfaces

--i-pageThe field everything sits on. Also the punched-out foreground when a theme's primary control inverts to a solid block of ink.
--i-planeA raised region — a near-transparent fill under a hairline, not a filled card. Panels, cards, rows, stats and zebra bands all read it.
--i-plane-2The second tier: a plane inside a plane, and the floating surfaces — tooltip and popover — that must separate from whatever is under them.
--i-wellRecessed, not raised. Verbatim machine output — logs, diffs, dry-runs — and the ground an input field is cut into.

Text

--i-inkText you are meant to read. Clears 4.5:1 against its own surface in every theme, light and dark; the visual gate checks it rather than an eye.
--i-dimSupporting text that must not compete — labels, meta, blurbs, trace lines. Load-bearing enough that its literals are measured, never eyeballed.
--i-faintThe tier that recedes furthest: placeholders, disabled controls, annotation numbers, the key half of a context fact.

Lines

--i-lineThe 1px boundary. The default edge of everything that draws one.
--i-line-hiThe same boundary, raised: what a hover moves to, the harder edge surface: outline draws instead, and the muted identity stripe.
--i-railThe 2px spine. A trace, a group, the rule under a table head.

Claims

Colour is a claim, never a coat of paint. These four are the entire hue budget of the product; selection, progress and emphasis ride on fill weight, rails and rings instead. Adding a hue needs a changelog note — hues are the scarce resource.

--i-signalThis wants you, or it binds you. Attention and obligation: the eyebrow labelling a region, the primary control, the focus ring, the stat that is waiting on a human.
--i-machineThe machine is speaking. Identifiers, paths, tool names, anything the system emits verbatim — and the "on" state, because selection is the system telling you what it currently holds.
--i-critThis failed. An outcome, never an emphasis — a failed run must never render in the ok tone, and a loud button must never borrow this one.
--i-okThis succeeded. The quiet outcome: it is the one claim with no wash token, so it colours text and an edge but never fills a surface.

Washes

A wash is the same claim carried at fill weight — how a state can colour a whole surface without introducing a second hue.

--i-signal-washBehind a primary button, a hot stat, a signal tag.
--i-machine-washBehind the selected pill, the on card, the active jump key.
--i-crit-washBehind a failure callout or tag. There is no ok-wash, on purpose.

Atmosphere

The page is lit from opposite corners by its two voices, with the origins off-canvas so only the falloff shows — that is what stops it reading as a decorative blob. Deliberately weaker than the reference it borrows from, because a workspace is stared at for hours rather than scrolled once. Note that no rule inside this package paints them: they are declared for the host's stage, and three of the six themes set them to transparent because those directions want no atmosphere at all.

--i-wash-machineThe machine corner, opposite it.

The two type voices

Mono is the machine; prose is the human. That split carries most of the identity, and it survives having no web fonts — which is the point. Themes ship into apps with no font loading, so the system leans on what system stacks genuinely give you: monospace against grotesque against a Georgia-class serif. That contrast is the biggest type lever available and it costs nothing.

--i-mono · the machine voice 836cd44cd560e171 · src/flightdeck/kernel/peer.py · gate PASS Headings, labels, identifiers, numbers, verdicts, traces, tags, table heads — anything the system emits or states about itself. Numbers set in it are tabular, so columns of them line up.
--i-prose · the human voice An agent scouts the fleet and files a proposal you approve or deny. Descriptions, help, chat, blurbs, the value half of a key/value pair, and what you type into a field. Capped at --i-measure (68ch) so a paragraph never runs the full width of a workspace.

Two derived faces

--i-display-face (figures and the page title) and --i-chrome-face (card titles, row titles, buttons, tags, table heads) both default to --i-mono. They exist because a theme whose display voice is not the machine voice was otherwise forced to restate that at six separate selectors — the symptom that a structure axis was missing. Editorial points both at its serif; the machine voice underneath is untouched.

The type ramp

Rendered at real size, with the token beside each step and the size it resolves to in the theme you are currently looking at. There is one fluid axis and it is the root font-size — clamp(16px, 0.7vw + 9px, 34px), set once in instrument.css. The ramp is therefore plain rem: it is already fluid through the root, and layering clamp() on top of a fluid root compounds the scaling, which was a v0.1 bug. --i-type-scale multiplies every step, and is the counterpart to --i-density: one scales text, the other scales space.

Density and type-scale move together

They are two levers on one decision. A theme that only tightened spacing ended up with cramped gaps around house-sized type, which reads as broken rather than dense — so Terminal moves both to 0.74, Editorial takes density to 1.35 with type at 1.06, and Blueprint condenses to 0.82 / 0.94. Both levers or neither.

The same coupling rule governs the grid: --x-stat-floor and --x-card-floor come from content — a stat is a short number plus a short label, a card carries a sentence — not from how many items one screen happens to pass. Tuning a floor so this screen's six items fit one row breaks the next screen's four.

Three border weights, three meanings

The weight is the message. A hairline separates; a rail attributes; a stripe identifies. Nothing in the system uses a fourth weight, and none of the three is decorative — if you find yourself reaching for 2px to make something look important, the answer is a role or a fill, not a thicker line.

Radius

One structural axis, --x-radius, and everything else derives from it — so a theme sets corners once. --x-radius: 0 squares the entire product, including pills, which is what Swiss, Terminal, Editorial and Blueprint all need. The boxes below are drawn from the derived tokens and print what they resolve to right now.

--i-radius
= --x-radius
--i-radius-sm
= --x-radius × 0.7
--i-radius-pill
max(×0.7, min(×100, 100px))
a real pill tags and pills read the pill token, so they square with everything else

Two traps recorded in the source, both worth reading before touching the derivation. Write 0px, not 0: the pill formula contains min(var(--x-radius) * 100, 100px), and a unitless zero makes that a number-versus-length mismatch — an invalid length that only looks right because border-radius falls back to 0 anyway. The component layer reads the derived --i-radius* trio, not --x-radius; across the component and shell layers the only rule reading the axis directly is the topbar tile. Bento, Editorial and Blueprint therefore bind the derived tokens in their own blocks — Editorial's note calls it a contract gap in as many words, and says it needs deleting the moment the component layer migrates.

The motion budget

Four durations, and they are not marketing-page numbers — this is a dense tool, read and operated rather than admired. Every one of them runs on the same easing curve (--i-ease), so motion in the product has one accent.

120ms · --i-press A control acknowledging the press itself, not just the result. Must feel instant. Expressed as scale, never translate: a button inside a row that translates nudges its neighbours, a scale is contained.
150ms · --i-fast Hover, focus, colour, border. The everyday transition — a control announcing itself, and the tooltip that names one.
260ms · --i-med A surface arriving or leaving: the popover, the drawer's backdrop, a disclosure expanding, the first paint of a tile collection.
300ms · --i-slow The full-height side card. The longest travel in the product, so the longest duration.

One discrepancy, reported rather than smoothed over: the budget written at the top of overlays.css lists the third step as 220ms, while tokens.css declares --i-med: 260ms. The token is what actually runs, so that is the number above; the comment is stale.

a lift, 150ms

What must never animate

  1. Anything that moves text the user is already reading. A list must not reflow under the eye.
  2. Anything on a hot path: streaming trace lines, table rows arriving, log output. The arrival animation on tile collections is deliberately not applied to .i-tr or .i-traceline for exactly this reason — rows and trace lines arrive while they are being read.
  3. The height of a scrolling region while it scrolls.

The positive form of the same rule: the tile rise runs only on the first paint of a collection, and only on opacity and scale. A list that animates on every update is fighting its reader.

Reduced motion is not "off"

Removing every transition takes away the signal that something arrived, which is precisely what a motion-sensitive user still needs. So travel and scale go — the drawer and popover stop translating — while opacity, which moves nothing, stays and stays fast. Under prefers-reduced-motion: reduce the four durations collapse to 1ms / 1ms / 80ms / 80ms.

Why there is no box-shadow

There is no box-shadow in this system, and that is a decision rather than an omission. Depth is translucency plus a hairline plus the page wash showing through. A shadow simulates a light source the rest of the product does not have; stack a few of them in dark mode and the near-black surfaces they fall on turn to mud, because a dark shadow on a dark field carries no contrast — only blur. Hairline-over-translucency stays crisp in both schemes because the edge is the depth cue and the fill is the distance cue, and both survive being inverted.

It also keeps the layering honest. A shadow makes anything look raised, so it lets you skip the question of what a surface is. Without one, a plane has to declare itself (--i-plane), a second tier has to declare itself (--i-plane-2), and something recessed has to be genuinely recessed (--i-well) — three named states instead of an arbitrary elevation number.

Two things that are not shadows and are allowed. Focus rings are outline — 2px solid var(--i-signal), offset, never removed — and outline is deliberately left free for that job. And Terminal draws its character grid with a zero-blur box-shadow ring on each cell, which is a hairline with a 1px spread rather than depth; painting it as a backdrop behind the grid instead lights up a solid block wherever a wrapped row runs short of cells, which is not something a character grid does. That exception is documented at the rule.
